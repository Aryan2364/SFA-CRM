# RGB SFA — plan

## 1. HOW TO USE THIS FILE

This section does not change between products. Leave it as written.

**Naming.** Every plan file is `plan-YYYY-MM-DD-HHMM.md` — four digit
year, two digit month, day, then a 24-hour time with **no colon**.
`plan-2026-08-31-1125.md`. Windows forbids a colon in a filename, and a
plan written on a Mac with `11:25` in its name cannot be checked out on
the machine this is built on. The date is when the plan was written, not
when the work happens.

**Supersession.** A plan is never edited into a new plan and never
deleted. When the plan changes materially, write a new file with a new
timestamp and leave the old one in place. The old file is the record of
what was believed at the time, which is the only thing that explains why
a decision was made. At the top of the superseded file add one line:

```
Superseded by plan-YYYY-MM-DD-HHMM.md on DD Mon YYYY.
```

**The pointer.** `plan.md` is two lines and nothing else. It is the only
file anyone has to know the name of:

```
Active plan: plan-YYYY-MM-DD-HHMM.md
Read that file before doing anything in this repository.
```

Update those two lines whenever a new plan supersedes the old one. If
`plan.md` points at a file that does not exist, every session starts by
guessing.

**Order of reading.** `AGENTS.md` is the rulebook and outranks this file
on anything to do with design or build. This file is product state: what
is being built, what has been decided, and what is still open. Where they
appear to conflict, `AGENTS.md` wins and the conflict is a bug in this
file.

`AGENTS.md` for this product lives at `D:\RGB_Software\rgb-kit-v2\AGENTS.md`
— a sibling repository, not inside this one. There is no copy here and one
must not be made; a second copy drifts.

## 2. PRODUCT

RGB SFA is a multi-tenant sales force automation admin panel: field sales
staff file daily activity, expenses, orders and leads against a weekly
plan, and their managers review, approve and score that work. It replaces
spreadsheet-and-WhatsApp reporting. Indian client, so `AGENTS.md` §18
applies as written — DD/MM/YYYY, lakh/crore digit grouping, `₹`.

This is **an existing product in production being brought into line with
the kit**, not a new build from it. That inverts the usual §0.1 order: the
screens exist and the token layer does not. Most sections of this plan are
thin because the product decisions were made long ago and live in
`CLAUDE.md` and `PLAN.md`.

Brand colour: deep indigo `#3D3A6E`. See §3.

## 3. LOCKED DECISIONS

1. **The seven brand tokens are settled and final.** Deep indigo. A
   dark-case brand: hovers lighter, presses darker, per `AGENTS.md` §2.2.
   This is a product decision for RGB SFA, not an external client brand.

   | Token              | Value     | Used for                                   |
   |--------------------|-----------|--------------------------------------------|
   | primary            | `#3D3A6E` | Resting state of main buttons, active tabs |
   | primary-hover      | `#4E4A87` | Mouse over. Lighter, not darker            |
   | primary-pressed    | `#2D2B52` | The instant of click                       |
   | primary-ring       | `#6864A3` | Keyboard focus outline                     |
   | primary-subtle     | `#EDECF4` | Selected rows, highlighted panels          |
   | primary-border     | `#D2D0E4` | Borders on primary-subtle surfaces         |
   | primary-foreground | `#FFFFFF` | Text and icons on primary                  |

   `primary-foreground` measures about 9.4:1 on `primary`, above the 4.5:1
   floor §2.2 requires. All seven are edited together as one block.

2. **Neutrals and status colours come from the kit unchanged** —
   `AGENTS.md` §2.3 and §2.4. Status colours do not move when the brand
   moves.

3. **The stack stays.** Next 14.2.35 / React 18 / Tailwind 3.4.1. The kit
   is Next 16.3.3 / React 19.2.8 / Tailwind 4 / shadcn. Upgrading a
   production app mid-restyle is a second project. Consequence, and it is
   not optional to understand: **the kit's `globals.css` cannot be
   copied.** `@import "tailwindcss"`, `@theme inline` and `@custom-variant`
   are Tailwind 4 syntax and compile to nothing here. The tokens port as
   `:root` custom properties plus `theme.extend.colors` entries pointing at
   them. Same tokens, same single source of truth, different declaration
   syntax.

4. **The API layer is out of this work entirely.** 115 routes, 7,514
   lines, no UI. The restyle surface is 51 `.tsx` files / ~12,400 lines,
   not the repo's 21,184.

5. **No second charting library.** `AGENTS.md` §21 names recharts, which is
   already a dependency here at 3.7.0.

## 8. WHAT A FAST MODEL WILL GET WRONG

1. **Copying the kit's `globals.css` verbatim.** It is Tailwind 4. See §3
   item 3. It will appear to work — Tailwind 3 ignores `@theme inline`
   silently — and every token will be undefined.
2. **Changing `--primary` alone.** All seven move together, or five shades
   keep the old brand. `AGENTS.md` §2.2.
3. **Mapping `text-gray-400` to `text-muted` as a like-for-like.** It is
   not. See §11 — it is a contrast fix that changes 200 call sites visibly,
   and that is intended.
4. **Touching `src/app/api/`.** 115 routes, no UI. The one exception is the
   email template in `auth/forgot-password/route.ts`, which is an HTML
   string, not JSX, and is out of scope anyway (§13 item 4).
5. **Treating `w-4.5` / `h-4.5` as valid.** 28 occurrences in
   `masters/page.tsx`. Not in Tailwind 3's scale, empty `extend`, so they
   compile to nothing and those icons are unsized today.

## 13. OUT OF SCOPE

Recorded so it is not rediscovered. **All four matter and all four come
after delivery.** None is a judgement that the work is unnecessary.

1. **The responsive pass at 1280 / 1024 / 768** — `AGENTS.md` §9. Includes
   the sidebar's two behaviours (icon rail below 1280, overlay below 1024),
   the 44px tablet touch targets, and rule 3's min-width shrinking. Not
   started, not measured.

2. **Empty and failed states** — `AGENTS.md` §13. Three distinct states,
   not one: nothing yet, nothing found, something failed. Not audited; the
   count of screens currently showing a blank area or the words "No data"
   is unknown.

3. **The permissions audit** — `AGENTS.md` §26. Hide whole areas, disable
   individual actions with a tooltip saying why, never show a control that
   fails after being clicked. This product has a real permission system
   (`src/lib/permissions.ts`, the `role_permissions` table) so §26 is
   enforceable here, but no screen has been checked against it.

4. **The email template** — `src/app/api/auth/forgot-password/route.ts`, 20
   hardcoded hexes. It is an HTML string sent by SMTP, not JSX. Email
   clients do not support CSS custom properties, so it cannot use the token
   layer and needs its own approach.
