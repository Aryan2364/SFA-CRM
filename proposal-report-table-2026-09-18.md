## 1. What §34 actually requires

| Rule | Requirement | How the component satisfies it |
|---|---|---|
| 34.1 | Total row sticky in the same way the header is; `position: sticky` on the **footer cells** as well as the `tfoot`, because several engines ignore it on `tfoot` | Delegated to the kit's `TableFooter sticky` prop, which already applies `sticky bottom-0` to `tfoot` *and* `[&_td]:sticky [&_td]:bottom-0`. No new CSS. |
| 34.2 | Never paginate; show every row and scroll | No pagination in the API, the component or the page. Bounded instead by the engine's `MAX_ROWS` (20,000) with a `truncated` flag the component renders as a banner. |
| 34.3 | First column freezes on horizontal scroll, with a 1px right border | `sticky left-0` on the first `th`/`td` of every row plus `border-r`. Applies to header, body and footer cells so the corner stays covered. |
| 34.4 | One component, every scope; where measures would multiply columns show one measure at a time, with the selector sitting **with the table**; row spine from the master list | One component, `<ReportTable>`, used by the builder and available unchanged to any record-scoped embed. One measure at a time is the engine's own shape — a `ReportSpec` carries exactly one measure. The measure selector sits in the toolbar directly above the table, at the table's own width. |

**§34.4's row-spine rule is the one I am deliberately not implementing, and it is a
finding rather than an omission.** "Every category appears whether or not it carries a
figure" needs the full master list for the dimension. `/api/reports/run` returns only
groups that have rows; `/api/reports/meta` returns dimension *keys and labels*, not
dimension *members*. The engine has no way to say "these are all nine expense
categories". Implementing the spine client-side would mean the UI fetching
`/api/masters/*` per dimension and mapping master rows onto group keys — a second source
of truth for what a dimension's members are, which is exactly what the registry exists
to prevent. **This belongs in P5-T1 as a `members` field on a dimension, or as an
`includeEmpty` flag on the run endpoint.** Raised, not worked around.

## 3. Proposed component APIs

Both are written as kit components that happen to live in the app, so promotion is a
file move plus an import rewrite. Neither imports anything from `@/lib/reports/**`,
`@/lib/db` or Prisma — see §5.

### 3.1 `ReportTable`

```ts
export type ReportFormat = 'amount' | 'number' | 'percent' | 'hours'

export type ReportTableRow = {
  /** One group key per dimension, in spec order. Identity, never displayed. */
  key: string[]
  /** The human label for each key, in spec order. */
  label: string[]
  value: number
}

export function ReportTable(props: {
  /** Column headers for the dimension columns, in spec order. One or two. */
  dimensions: { key: string; label: string }[]
  /** The measure, which names and formats the single value column. */
  measure: { key: string; label: string; format: ReportFormat }
  rows: ReportTableRow[]
  /** The engine's own grand total — NOT a sum of `rows`. See below. */
  total: number
  /** True when MAX_ROWS bit and the figures are partial. Renders a banner. */
  truncated?: boolean
  /** Section 34.4's scope prop: what the figures cover, shown as caption text. */
  scopeLabel?: string
  /** Fills the height it is given; the caller owns the layout. */
  className?: string
}): JSX.Element
```

Three decisions worth stating:

- **`total` is a prop, not a computed sum.** For a `ratio` measure such as Discount
  Percentage the grand total is `sum(numerator) / sum(denominator)`, which is not the
  sum *or* the mean of the row values. `runReport` computes it correctly against a
  separate accumulator. A component that summed the column would print a wrong number
  that looks right.
- **`key` is carried but never rendered.** It is React's row identity, which is what
  keeps a row updating in place rather than being destroyed and recreated when the
  measure changes under the same dimension.
- **Numbers right-aligned with tabular figures, labels left** (§11.1). Right alignment
  on a column read as a column is the whole reason the digits line up.

### 3.2 `DateRangeControl`

```ts
export type DateRangePresetKey =
  | 'today' | 'yesterday' | 'last_7' | 'last_30'
  | 'this_month' | 'last_month' | 'last_3_months' | 'this_fy' | 'custom'

/** Pure, exported for testing and for anything else that needs the same maths. */
export function resolvePreset(
  key: Exclude<DateRangePresetKey, 'custom'>,
  today: Date,
): { from: string; to: string }   // YYYY-MM-DD, inclusive both ends

export function DateRangeControl(props: {
  value: { preset: DateRangePresetKey; from: string; to: string }
  onChange: (next: { preset: DateRangePresetKey; from: string; to: string }) => void
  className?: string
}): JSX.Element
```

- The value is `{ preset, from, to }` rather than `{ from, to }` alone so the chosen
  preset survives a round trip. A saved report (P5-T3) that stored only the dates would
  reopen in March still showing January's dates; storing `last_30` reopens as the last
  thirty days, which is what "This financial year" and "Last 30 days" mean as *saved*
  choices. `custom` is the one case where the dates are the value.
- `resolvePreset` is pure and takes `today` as an argument rather than reading the
  clock, so the financial-year boundary is testable without mocking time.
- Financial year: April to March. On 18 September 2026 "This financial year" resolves to
  `2026-04-01 … 2027-03-31`.
- Dates are produced as `YYYY-MM-DD` strings built from local calendar parts, never
  `toISOString()`, which would shift the boundary by a day in IST.

## 5. The bundle hazard, stated because it is the way this task fails

The report builder is a heavy client page, and everything it needs to know about
measures and dimensions lives in `src/lib/reports/`, which imports `@/lib/db`, which
imports Prisma and `pg`. **A single `import type` from there that is not `import type`
pulls Prisma into the browser bundle and breaks every route in the application, with a
clean `tsc --noEmit`.**

So the wire shapes are re-declared in `src/components/reports/types.ts`, which imports
nothing. They are duplicated on purpose: the alternative is a client page reaching into
the server's data layer for a type, and the duplication is bounded by the fact that both
sides are the JSON on the wire, which is the contract anyway.
